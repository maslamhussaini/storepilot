Refresh policy
--------------
Shopify currently reports expiring offline access tokens with expires_in
normally around 3,600 seconds. StorePilot derives the actual expiry from
Shopify's expires_in response. Shopify recommends refreshing shortly before
expiry (often a few minutes ahead). StorePilot uses a 60-second proactive
safety window before the recorded access-token expiry. That threshold is
StorePilot's implementation policy, not a Shopify-mandated constant. A literal
one-hour threshold would make every newly issued token immediately
refresh-eligible. Explicit forced refresh remains available.

Concurrency and atomicity
------------------------
- A database lease prevents simultaneous refresh completion.
- Credential-generation checks reject stale OAuth/refresh writes.
- OAuth reauthorization clears refresh claims and increments the generation.
- Transient failures release the claim without changing connection status.
- HTTP 401 transitions to `reauth_required`, deletes invalid Vault material,
  preserves history, and emits one idempotent event.
- Malformed responses and non-401 permanent failures never partially persist.
- No second token-storage mechanism was introduced.
